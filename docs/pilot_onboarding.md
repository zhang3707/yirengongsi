# Pilot 用户招募与使用说明（v1）

> 用途：给第一批真实用户看的"上手照着做"文档。
> 目标：30-90 天 Pilot 期内，5-10 名用户在 3-5 个真实场景上使用此平台，并沉淀 ≥10 条评价。

---

## 一、这是个什么系统（30 秒版）

**不是聊天机器人，是一台 AI 员工。**

你提交一个**任务**（不是聊天），系统会：

```
接收任务 → 挑选合适的 AI Agent → 按顺序执行技能 → 生成 Markdown 报告 → 全程留痕
```

你拿到的是**可以直接用的 Markdown 报告**（能复制、能粘贴、能引用），而不是一堆闲聊。

你还能看到它到底干了什么（每一步、耗时、重试）——**过程透明，不是黑盒**。

---

## 二、怎么开始（3 分钟）

### 1. 打开控制台

浏览器访问：<http://localhost:8000/console/>

（如果部署在内网或远程，请使用运维给你的地址。）

### 2. 是否需要填 Token？（取决于服务方有没有开启认证）

- **如果服务方没开认证**（默认）：直接用，**Token 框留空**即可。
- **如果服务方开了认证**：点右上角"保存"前，把 Token 粘进输入框。
  Token 会存到**你自己浏览器**的 localStorage，不会存服务器、不会提交到仓库。
  Token 错了会弹 401 提示，重新输入即可。

### 3. 提交第一个任务

左侧"提交任务"面板，推荐先用这 3 类任务练手：

| 场景 | 任务类型 | 示例标题 |
|---|---|---|
| **信息研究** | `research` | 收集某领域 3 个竞品的最新动态与差异点 |
| **分析决策** | `analysis` | 分析这条产品反馈：某功能使用率低，是设计问题还是门槛问题 |
| **内容生产** | `content` | 基于这份会议纪要生成一篇对外可用的总结 |

字段含义：

- **任务名称**：人一眼能懂的一句话标题；
- **目标**：你到底想要什么（越具体越好，比如"3 个要点 + 1 条风险 + 1 条建议"）；
- **任务类型**：`research` / `analysis` / `content` / `workflow` / `general`；
- **优先级**：默认 P2；
- **提交人邮箱**：建议填真实邮箱，反馈闭环时能对上。

点"提交并运行"，等系统跑完 5 步（快则 2 秒，真实模型时约 30-60 秒）。

### 4. 看结果

右侧"任务详情"会显示：

- **5 个步骤**：`task_receive → agent_select → skill_execute → result_generate → save_record`，每步的起止时间与耗时；
- **Markdown 报告正文**：可直接复制使用；
- **使用的 Agent 与耗时**。

### 5. 提交 Pilot 评价（重要！）

每个任务详情最下方有一行"Pilot 评价（1-5 分）"：

- **质量**：结果值不值得用？
- **体验**：操作顺不顺？
- **信任**：敢不敢直接拿去用？
- **原耗时(min) / AI耗时(min)**：你原本自己做要多久 vs 今天 AI 帮你跑完多久；
- **愿意复用**：会不会再让它做同类任务？

**这是 30-90 天 Pilot 的核心数据**，请每次用完 30 秒把这 5 个格子填完。
填完会自动计入右侧"Pilot 指标"面板。

## 三、不顺畅时怎么办

| 情况 | 怎么办 |
|---|---|
| 任务提交 401 / Token 无效 | Token 错了 → 点"清除"→ 重新粘贴正确的 Token |
| 任务一直 `running` 不返回 | 等（真实模型约 30-60s），2 分钟仍无反应记 Bug |
| 报告其实是"编"的（比如没有真实资料来源） | **这是要重点反馈的问题**，反馈时贴出任务 "id" |
| 不知道怎么描述任务 | 把你要干什么原话写进去，让系统去理解；不要先自己拆小 |
| 其他问题 | 在右侧"任务详情"下面找到任务 id，报给服务方 |

## 四、什么是"Pilot 目标"（为什么要填评价）

- **本系统不像 ChatGPT 是个通用助手，它是一个面向特定任务的 AI 员工。**
- 30-90 天 Pilot 的核心目标不是"演示一次成功"，而是**找出哪些场景真的值、哪些不值**。
- 哪些做、哪些不做：
  - ✅ **做**：真实业务中每周都在做、有固定格式的任务（周报、竞品动态、会议纪要）
  - ⚠️ **慎重**：需要强外部依赖（如实时爬取私有数据库）或强判断（定价、法律意见）
  - ❌ **不做**：一次性、无处上下文、需要强外部对接的"一次即弃"需求
- **如果"乐意复用"比例 < 30%，优化方向是"给某类任务建专属模板"而不是做新功能。**

---

## 五、日常流程建议（30 分钟/天）

1. **早上 10 分钟**：看 Pilot 指标（任务数 / 成功率 / 评价数）
2. **事中 15 分钟**：遇到合适任务就提交一个，用完立刻评价；
3. **随时 5 分钟**：遇到 Bug / 报告不准 → 在"反馈池"（见下）或直接告诉服务方。

反馈池是 Pilot 的"Bug+建议收口"，**每次真实 велу都值得记一条**（一分钟就够）。

---

## 六、给服务方的话（你不用看这段）

- Pilot 完成后应至少拿到 ≥10 条真实评价；
- 重点看"质量 4 分以下"与"乐意复用 = 否"的分档；
- 根据反馈池 P0/P1 问题，一周内修；P2/P3 进需求池，Pilot 运行期间**不再开新功能**。
